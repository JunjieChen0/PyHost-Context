## 0. 一句话定位

把课题从"再多扰动几个环境变量"收紧为：**发现 Python 测试中的隐式环境假设，并对"如何修复这些
假设而不削弱测试"给出可审计的评估**。可行性研究已经证完"能测到差异"；本研究要回答的是差异
**有多普遍、来自什么、修得掉吗、修完还测得出来吗**。

## 1. 贡献定位与新颖性边界

**潜在增量**：跨项目的受控测量（配额样本，见第 5 节的总体限定）、根因证据（两轴构造 + 实际读取层
与调用链）、保持语义的修复评估（三策略 + 有正控制与目标断言的变异探针）。

**明确不主张的新颖性**：不是"Python ＋ 环境变量"；也不是 Python 生态的概率抽样。近邻已有
flake-exorcist（TZ / locale / 哈希种子扰动与环境依赖分类）与 ChaosAPI（主动控制 API 行为发现
测试问题）。本研究把二者分别作为**工具策略对照**与背景，而非重复其贡献。

**与可行性研究的关系**：可行性研究提供方法与仪器（三态启动环境、三视图证据、逐轮状态恢复、
进程组清理、E0—E4 等级、A1→B→A2 恢复块），并提供"现象确实存在"的实例；本研究提供**知识**。
两者分母严格分开。

## 2. 三个研究问题与判据

### RQ1 影响：哪些隐式环境假设会让测试结果变化，影响是否跨项目、跨类别出现？

- **单位**：`unit = 项目 × K 条件`（每项目 8 个）。**主统计单位是项目**，不是测试节点。
- **确认判据（先于执行固定，机械可判）**
  1. 扰动轮 5/5 各自同一（身份集合、失败签名、阶段三态跨轮一致），且 A 与 B 不同；
  2. 翻转节点集在 5 个扰动轮内**完全相同**；
  3. 该翻转节点集里的**任何节点，在 45 次独立等预算 B0 对照中都没有翻转过**；
  4. session 完整、扰动有效、无超时。
- **判据 3 的含义（修订）**：这是**操作性筛查标准**——说明在本样本与本仪器下未观察到该节点的
  低频不稳定。它**不是**"不存在 flaky"的证明。
- **报告量**：确认 unit 数／全部 unit 数；至少一个确认 unit 的项目比例（Wilson 95% 区间，
  **分母写明是探索组还是全样本**）；类别层比例（Clopper–Pearson，仅描述性）；每项目翻转节点数与
  **独立机制数**（二者不得混同）。

### RQ2 根因：变化来自产品功能问题、测试隔离不足、合理表示变化，还是证据不足？

**修订：改用两个正交轴 + 附加标签，取消"首个匹配者生效"的单标签归类**，以免同时成立的事实互相隐藏。

| 轴 | 取值 | 规则 |
|---|---|---|
| **产品契约符合性** | `conformant` / `violates_contract` / `unknown` | `violates_contract` 必须引用该环境下的契约出处；**仅 B 与 B0 不同不能推出功能缺陷** |
| **测试是否显式建立其断言的环境** | `explicit` / `ambient` / `unknown` | `ambient` = 依赖环境却不断言建立它 |

**附加标签**：`representation_only`（差异只落在显示或排版表示上、载荷无功能性差异；**可与任一轴
取值共存**）；`reading_layer` ∈ {product, stdlib, dependency, test, fixture, plugin, launcher, unknown}
——登记**实际读取变量的层**与调用链。**产品自身不读变量不等于证据不足**（可行性研究的 Click 案例
本来就涉及测试里委托的 optparse）。

**每个确认 unit 必须产出**：最小复现、读取层与调用链（`file:line`）、断言路径与规范依据、两轴取值
与标签、**机制标识**。

**机制定义**：机制 =（读取层 + 产品/依赖路径 + 测试假设 + 契约状态）。**机制计数不得直接等同任何
一个轴的取值计数，也不得等同失败节点数。**`unknown` 一律保留为 `unknown`，不向上取整。

**可审计性（修订：分类前写清）**：盲复分类的**抽样单位**是确认 unit（不是测试节点）；比例
**ceil(20%)**、至少 1 个；随机种子 `pyhost-context-extension-reclass-v1-20261015`，按该 seed 对
单位规范标识做 SHA-256 排序取前 N；**复核者可见**最小复现、读取层与调用链、断言位置、两轴证据、
原始观察与归档证据；**隐藏**作者的轴取值、标签与机制标识；报告原始一致率、不一致清单与参与单位数。

### RQ3 修复：三种策略分别消除了什么，又保留或遗漏了什么？

| 策略 | 要回答的问题 |
|---|---|
| **R1 全局固定环境** | 是否只是让问题不再出现？**全局固定会把有效运行上下文改为 Z**，必须记录 `effective_context`，**不得**声称修复后的套件"仍在原 B 中通过" |
| **R2 测试局部隔离** | 是否明确建立了该测试需要的前置条件，且不依赖会话级全局设置？ |
| **R3 显式环境参数化** | 是否同时覆盖了产品原本应支持的不同环境行为？ |

**策略状态**：`not_applicable`（对该机制不适用）／`tried_but_failed`／`passed`——三者**分别计数，
全部保留在分母**。

**判据（A、B、C 必须同时成立）**

- **A 失败消失**：在**有效运行上下文**中，修复后该 unit 的翻转集为空。
- **B 义务保留（修订为语义判据）**：**有规范依据的有效义务不得削弱**——不是"断言必须逐字不变"。
  必须列出原义务与新义务及各自的规范对应；**修正过度指定的表示断言、按环境参数化预期值属于合法
  修复**；不得删除、跳过、xfail 或放宽任何有规范依据的有效义务；机械 diff 列出全部断言相关改动；
  修复后套件在**未变异**的产品上，B0 与有效运行上下文中都必须通过。
- **C 覆盖仍存（修订为有归因的行为验证）**：由**有归因证据**的变异探针证明，而非任意非零退出码。
  必须记录：被改变的行为与规范依据、**目标测试与目标断言（nodeid + 断言文本）**、**预期的失败阶段
  与失败签名**；**排除非目标失败**（语法错误、导入/安装错误、无关 fixture/初始化错误、其它测试本来
  就失败，均不算命中）；**变异的正控制**——必须证明该变异破坏的正是目标义务（原始套件下该变异也使
  目标测试失败）；探针构造与取舍规则**提前固定**，**全部尝试保留归档**，不得反复挑到能杀死的那一枚
  才报告。
  **边界**：单枚变异被杀死的结论只能是"对该探针仍敏感"，**不能**证明全部断言义务未被削弱。

**每个策略的运行矩阵（修订：补上缺失的格子，5 格）**

| 格 | 套件 | 产品 | 上下文 | 期望 |
|---|---|---|---|---|
| 1 | 修复 | 原始 | B0 | **通过** |
| 2 | 修复 | 原始 | 有效运行上下文 | **通过**（判据 A） |
| 3 | 原始 | 原始 | B | **失败**（原观察参考） |
| 4 | 修复 | **变异** | 有效运行上下文 | **在目标断言上失败**（判据 C） |
| 5 | 修复 | **变异** | B0 | **在目标断言上失败**（判据 C） |

每策略 5 次，**每单位 15 次**。**D 覆盖范围**单独报告：该策略是否覆盖产品原本应支持的其他取值，
是否遗漏 B0 与 B 之外的第三种行为。**变绿不算修复成功。**

## 3. 样本：采样框、顺序、版本、准入、替补

**规模目标：30 个项目 = 探索组 20 + 独立验证组 10**，五类各 6（CLI／时间与国际化／文本与配置／
数据处理／开发测试工具）。30 是**可执行的设计目标**，不是 CCF-B 的录用门槛。

### 3.1 采样框、顺序与准入前纪律

- **框来源**：`top-pypi-packages-30-days.min.json`（月度下载量快照，BigQuery），按 **SHA-256** 绑定；
  本协议使用 `last_update = 2026-10-01T12:40:51Z` 快照，15,000 行。
- **顺序**：按 `download_count` 降序的名次即选样顺序。
- **窗口**：取快照前若干名，准则是**五个类别各自 ≥ 20 个元数据合格候选**（配额 6 的三倍余量）；
  该准则与任何候选的测试结果无关，且在抽取之前确定。本次实际窗口 = 前 **2,304** 名。
- **准入前纪律**：在样本选定**之前**，**不得**检查任何候选是否读取环境变量，**不得**按"看起来会读
  环境变量"筛选、排序或替换；主样本必须能解释**一般项目**中的影响范围。

### 3.2 版本规则（修订：落实版本时点）

- **规则**：取**截止时点（`2026-10-01T12:40:51Z`）之前已上传**的最新**正式**发布版本，且该版本存在
  sdist。预发布与开发版不参与"最新版本"比较（与 pip 默认行为一致）；只有该项目没有任何合规正式
  版本时才退回预发布并标注。
- **实现**：按 `releases[*][*].upload_time_iso_8601` 过滤后再比较版本；**不使用** `info.version`
  （那是当前最新版，不是截止时点的版本）。
- **逐候选记录**：选定版本、sdist 上传时间、元数据获取时间、sdist SHA-256、wheel SHA-256。
- **无合规版本**：记 `excluded`（`version_rule:no_sdist_release_at_or_before_cutoff`），**不**换用
  截止日之后的版本。**不得**为得到更好看的结果更换版本。

### 3.3 排除集（修订：恢复既有约束）

`A1` 排除 **可行性阶段 8 个项目**，以及**用户此前明确要求不作为新样本**的项目：

| 项目 | 理由 | 别名一并排除 |
|---|---|---|
| Flask | 上一研究（PyCompat-EnvSelect）的校准项目 | `Flask` |
| Arrow | 上一研究的独立项目（Arrow 1.2.3 / dateutil 窗口） | `Arrow`、`pyarrow`、`apache-arrow` |
| Rich | 上一研究的独立项目，且发生过 NO_COLOR 未冻结的复现缺口 | `Rich` |

名称比较按规范化（`-`/`_`/`.` 统一）后进行。**不得静默解除旧约束。**

### 3.4 准入条件（按固定次序施加；A5—A8 只用 B0 证据）

| 编号 | 条件 |
|---|---|
| A1 | 不在排除集内（3.3） |
| A2 | sdist 内含测试文件，是自带测试套件的项目而非元包/空壳 |
| A3 | 纯 Python：有 `py3-none-any` wheel；sdist 无 `.c/.pyx/.rs/.go` 与 `ext_modules` |
| A4 | sdist 体积 ≤ 15 MB |
| A5 | 该版本可装入冻结 venv 并 `uv pip check` 成功 |
| A6 | `pytest --collect-only` 成功且收集 ≥ 50 个测试 |
| A7 | 基线可用且单轮耗时 ≤ 60 s；无外网需求、无外部服务 |
| A8 | 起始源码树可由冻结 sdist 逐字节恢复，重复两次一致 |

**A7 的基线分类（修订）**

- **可用**：存在一次完整会话、逐测试结局可归并、至少一个测试通过。
- **稳定失败**：基线中稳定失败的测试**保留**为观测，基线判为"可用但带失败"，并计入 45 次 B0 对照
  的噪声底；**不得**改判为不可用。
- **收集错误**：收集阶段错误或返回码与 `SessionFinished` 不一致 → 候选不可用。
- **skip / xfail**：如实记录，既不算通过也不算失败；skip 比例不构成拒绝理由，但必须披露。
- **时长不是充分条件**：单轮 < 60 s 必须**同时**满足会话完整、无收集错误、无超时、源码树可恢复。
- **工具栈身份冲突**：被测项目与固定运行栈同名时（例如候选 `pytest` 与冻结 `pytest 7.2.0`），
  按既定规则**记录并淘汰**；**不得**把安装树里的被测版本换成另一版本后仍称固定栈。依赖更新版
  pytest 的插件若无法在冻结栈下满足其测试依赖，**如实淘汰**，不临时放宽栈。

**准入只能用 B0 证据；扰动条件的结果不得影响样本构成。**

**成本上限（预注册）**：全部选定项目的单轮 B0 基线耗时之和 × 50 × 2 若超过 **60 小时**，按基线
耗时降序排除直至落入上限，**在跑任何扰动轮之前**执行并逐条记录。

**替补规则**：类别内候选准入失败，取该类别**名次下一个**候选，最多替补 5 次；逐条记录被替换者、
替补者、原因；不得改变类别配额，不得事后调整类别定义。

### 3.5 类别配额与归类规则

- **归类**：**固定有序规则**，首个命中者生效；判定材料只用 (i) PyPI 主题分类器，再 (ii) 项目**名称**
  中的固定词表（按 `-`/`_` 精确分词，不用子串匹配）；平局按协议中固定的类别次序裁决。
- **归类在任何准入运行之前完成**，归类表整体哈希后冻结。
- **操作性类别声明（修订 N2）**：类别是**操作性的**，不是生态学构念，误归类透明披露。本次在**任何
  候选测试结果之前**做过**一次有记录的词表校正**：从 cli 规则中删除 `Topic :: System :: Systems
  Administration`（过宽，把打包/系统工具扫进"命令行工具"）。此后**不得**再按阳性结果调整分类。
  残留的误归类（例如 `matplotlib-inline` 因名称分词命中 `matplotlib` 落入数据类）**如实披露**。
- **未归类**项目记 `uncategorized`，在配额抽取中跳过，不强行塞进任何类别。

### 3.6 探索组与验证组

类别内按名次把准入通过者排序：**前 4 个 → 探索组**，**其后 2 个 → 独立验证组**。

**修订：这按流行度偏移的留出验证（rank-shift holdout），不是随机同分布的验证**，报告按此解释。

**纪律**：探索组分类与修复规则**冻结之前**不得分析验证组数据；不得用验证组调整规则、条件或判据；
**验证组的主矩阵照常执行**（它是已承诺的测量）；G1/G2 只决定后续修复投入与投稿定位。

## 4. 设计与对照

### 4.1 主矩阵

条件为 B0 + K01_TZ / K02_LC_ALL / K03_LANG / K04_HASH / K05_NO_COLOR / K06_TERM / K07_COLUMNS /
K08_LINES，取值与三态模型沿用冻结协议，不做任何调整；每 unit 5 次；30 × 9 × 5 = **1,350** 次
（其中 B0 占每项目 5 次）。仪器、三视图证据、逐轮状态恢复、进程组清理、网络规则、超时处理全部
沿用 `matrix/tooling/`。

### 4.2 等执行预算 B0 对照（修订：真正的独立追加）

- **每项目另外运行 45 次 B0**，共 **1,350** 次；**不复用**主矩阵里的 5 次。每项目 B0 合计 **50** 次，
  两个账本的 `run_id` **不重叠**。主矩阵 + 独立对照 = **2,700** 次。
- **作用**：噪声底；使 RQ1 判据 3 可判；回应"五次一致不能证明不存在低频不稳定"。
- **调度**：与主矩阵轮**交错**执行（冻结 seed 生成交错调度并于运行前哈希），避免把机器漂移误读为
  环境效应。
- **记账**：与主矩阵分开记账，同属一个批次承诺。

### 4.3 工具对照：flake-exorcist（修订 N1）

- 版本 `0.1.0`，独立 venv，冻结解释器同版本。
- **不是等价干预**：工具按**自己的维度策略**同时改动一组因素，那是"工具原生策略"的比较，
  **不是**单变量因果干预。比较开始前固定记录：实际调用与参数、每个维度实际改动的变量集合与取值、
  **随机种子与 PYTHONHASHSEED 是否同时改变**、启动进程数与重跑策略、成本口径与失败处理。
- **允许的比较**：只比较"工具策略 vs 本研究单键协议"在**共同覆盖的变量类别上**的检出结果，并逐条
  披露差异。**不得**把同名维度宣称为与 K01—K04 完全等价的干预。
- **覆盖披露**：工具独有 ORDER / PARALLEL；本研究独有 K05_NO_COLOR / K06_TERM / K07_COLUMNS /
  K08_LINES。工具自身派发的 pytest 进程**另列预算行**。

### 4.4 恢复复核

沿用 A1→B→A2、每合格单位最多 2 块、参照位于块内第 1、3 位、两批顺序为哈希序与严格反序。
**修订**：潜在单位 240（30 × 8），足额覆盖上限 2 块 × 3 轮 × 240 = **1,440** 次。若上限生效，
按**冻结 seed 的规范标识 SHA-256 排序**依次处理（**与阳性强弱、方向、类别无关**）；未处理到的
合格单位记 `not_confirmed_within_budget`，**保留在分母**，不得当作无效应。

### 4.5 修复验证

**每单位 15 次**（3 策略 × 5 格，第 2 节判据表），足额覆盖上限 240 × 15 = **3,600** 次，
分配规则同 4.4，未处理到的记 `not_repaired_within_budget` 并保留分母。补丁与变异各有 SHA-256，
全部探针尝试归档；修复在**独立补丁分支**上进行，原始测量工件不变。

## 5. 统计总体、估计量与区间（修订）

- **总体限定**：本研究是**热门、纯 Python、自带测试、且满足运行时长与工具栈门槛的配额样本**
  （下载量名次配额抽样）。**不是** Python 生态的概率抽样——按下载排名确定性取样并固定五类配额，
  没有抽样覆盖保证。区间（Wilson / Clopper–Pearson）在披露模型假设的前提下报告，**不得**称为生态
  患病率或生态比例；每处比例都写明**分子、分母与所在总体**。
- **留出验证的解释**：类别内前 4／后 2 是**按流行度偏移的留出验证**，不得写成随机同分布验证。
- **主要估计量**：至少一个确认 unit 的项目比例（Wilson 95% 区间），分母写明是探索组还是全样本。
- **两个端点分别定义（修订）**
  - **分类一致率**：分子 = 验证组中分类规则复现的轴取值与独立参考分类一致的确认单位数；
    分母 = 验证组中**有独立参考分类**的确认单位数。`unknown` / 无确认单位的项目**不计入分母并单列**。
    分母为 0 时记**"无可评价案例"**，**不得**记 100%。
  - **修复判据达成率**：分子 = 同时满足 A、B、C 的（单位 × 策略）数；分母 = 实施过该策略的
    （单位 × 策略）数；`not_applicable` / `tried_but_failed` / `not_repaired_within_budget` **分别单列**。
    分母为 0 时同样记"无可评价案例"。
- **确认成本**：每个确认单位消耗的执行次数与机器时间，按项目与按类别报告。
- **明确不做**：不把 5 次重复当统计功效依据（单次失败概率 0.10 时 5 次至少一次失败概率 0.40951）；
  不把测试节点数当独立发现数或独立机制数；不把"未观察到差异"写成"无作用"；不把任一轴线上的
  `unknown` 向上取整。
- **低频不稳定**：由 45 次独立 B0 对照给出可报告的翻转率，不用"5 次一致"承担"不存在 flaky"的任务。

| 预算行 | 计算 | 上限 |
|---|---|---|

  在 10 个量级，恢复约 60 次、修复约 150 次。**上限是为了不必事后临时发明截断规则**，不是预期工作量。

  估算再启动**，成本上限规则见 3.4。

  返回条数"推断、批次自校验不过按中止处理；失败尝试与引航**另列**，不混入分母。

## 7. 停止与决策规则

**这些门是项目投入与投稿定位的决策规则，不是 CCF-B 录用标准。**

- **G1 跨项目重复机制（修订为确定规则，二取一）**：至少 3 种不同**机制**各在 ≥ 2 个项目中出现；
  **或**至少 1 种机制在 ≥ 4 个项目中出现。机制按（读取层 + 路径 + 测试假设 + 契约状态）判定，
  **不按表面现象判定**——因此**同一种 ANSI 机制跨 4 个项目出现时，G1 是成立的**（不再有"只剩
  ANSI 与帮助排版即不成立"这种与之矛盾的举例）。
- **G2 可审计修复**：至少 2 个（单位 × 策略）同时满足 A、B、C，且变异探针在**目标断言**上按预期失败。
- **G3 验证支持**：分别报告**分类一致率**与**修复判据达成率**（分子分母见第 5 节），不设无分子的
  "统一 70% 通过"表述。
- **验证组照常测量**：G1/G2 只决定修复投入与投稿定位，**不取消**已承诺的验证组主矩阵。
- **提前停止（若有）**：默认不停止；若用户坚持提前停止，须预注册条件式分析，并**明确不能再声称
  完整 30 项目的影响测量**——主结果只能报探索 n = 20，其余 10 个项目记**未执行**，不得当阴性。
- **禁止**：看到结果后新增项目、更换版本、调整条件取值、重跑到满意为止、按阳性结果调整分类词表或判据。
